# Публикация LEXIS на Netlify

Этот проект можно безопасно опубликовать на временном адресе Netlify вида
`https://<имя-проекта>.netlify.app`. Публичные страницы будут полностью
работоспособны: навигация, адаптивный дизайн, формы и демонстрационный
интерфейс.

## Что настроено в репозитории

- `netlify.toml` собирает проект командой `npm run build` и публикует папку
  `dist`;
- все прямые ссылки отдаются через React-приложение, а не приводят к 404;
- для статических ресурсов включено долговременное кеширование;
- при отсутствии переменных production API личный кабинет не пытается
  подключаться к закрытому серверу и не показывает вымышленные данные.

## Создание сайта в Netlify

1. Войти в Netlify через GitHub.
2. Выбрать **Add new site** → **Import an existing project**.
3. Подключить репозиторий `Classicart54/lexis-content-pipeline-bot`.
4. Если фронтенд хранится в отдельной папке, указать её как **Base directory**.
   В текущей локальной структуре это папка, где лежат `package.json` и
   `netlify.toml`.
5. Проверить параметры: build command — `npm run build`, publish directory —
   `dist`. Обычно Netlify прочитает их из `netlify.toml` автоматически.
6. Нажать **Deploy site**.

## Безопасный временный режим

На Netlify **не нужно** задавать `VITE_PIPELINE_LIVE=true`, пока не создан
защищённый API-адрес на стороне production-конвейера. В этом режиме кабинет
остаётся демонстрационным; он не показывает фиктивные заявки и не делает
попыток читать закрытые production-данные.

## Как включить реальные данные позднее

После появления домена кабинета и HTTPS reverse proxy на production-сервере
в Netlify добавляются переменные окружения:

```text
VITE_PIPELINE_LIVE=true
VITE_PIPELINE_API_URL=https://workspace.example.com/api
```

`workspace.example.com` — будущий адрес API кабинета, не IP-адрес сервера.
Production API должен принимать этот origin, работать только по HTTPS и
проксироваться к loopback API конвейера. Подробный серверный план лежит в
`pipeline-service/docs/web-dashboard-deployment.md`.

После сохранения переменных нужен новый deploy: Vite встраивает публичные
переменные `VITE_*` в собранный фронтенд. Никакие токены, пароли, Telegram-
ключи или `CONTENT_API_TOKEN` в Netlify не добавляются.
